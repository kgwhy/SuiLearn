## 1. 产品定位

随心学 SuiLearn 是一款 Android 本地学习 App。第一版聚焦 Java 八股学习场景，目标是做出一个无需登录、开箱即用、能刷题、能复盘、能主动查知识点的个人学习工具。

第一版不追求复杂 AI 能力和多学科扩展，而是先证明一个最朴素但真实可用的闭环：

> 用户每天愿意打开 5 分钟，刷几道 Java 八股题，复盘错题，并能在想补某个知识点时快速找到相关内容。

## 2. 第一版目标

第一版直接按最终交付范围定义，对应 `docs/chat.md` 对话中 v0、v1、v2 的合并范围，不再拆成多个对外版本或阶段目标。开发过程中可以按任务拆分推进，但产品验收只看第一版整体是否形成完整可用的 Java 八股本地学习工具。

第一版目标：

> 让用户无需登录即可打开 App，围绕 Java 八股完成刷题、复盘、搜索和知识点专项学习。

第一版需要同时满足三类核心价值：

- 能刷题：用户可以通过顺序、随机、分类、知识点、错题等方式进入练习。
- 能复盘：用户答错后可以沉淀到错题本，结合收藏、解析、统计持续复习。
- 能主动学：用户可以搜索题目和知识点，围绕某个概念查看关联题目并专项练习。

第一版完成后的理想状态：

> 用户准备 Java 面试时，可以真实依赖 SuiLearn 完成日常刷题、错题复盘和知识点查漏补缺，而不是把它当作临时 demo。

## 3. 目标用户

第一版目标用户是正在复习 Java 面试知识的个人开发者，尤其是：

- 准备 Java 后端面试的人。
- 想利用碎片时间复习 Java 八股的人。
- 想把错题、知识点和复习进度沉淀在本地工具里的人。
- 当前阶段的核心用户也包括项目创建者本人。

## 4. 核心使用场景

### 4.1 碎片时间刷题

用户打开 App 后，可以快速进入刷题，无需登录、无需配置、无需选择复杂条件。

典型流程：

1. 打开 App。
2. 选择继续刷题、随机刷题或某个分类。
3. 回答题目。
4. 查看答案和解析。
5. 进入下一题。

### 4.2 面试前集中复习

用户在准备面试前，可以按 Java 八股分类集中复习。

典型流程：

1. 进入分类页。
2. 选择 JVM、集合、并发、Spring、MySQL 等分类。
3. 查看该分类进度和正确率。
4. 进入分类刷题。
5. 复盘分类下的错题。

### 4.3 错题复盘

用户刷题后可以回到错题本，集中处理薄弱题目。

典型流程：

1. 进入错题本。
2. 按全部错题或知识点筛选。
3. 查看题目、正确答案、解析。
4. 重新练习。
5. 对已经掌握的题目标记为已掌握。

### 4.4 主动搜索知识点

用户突然想复习某个概念时，可以直接搜索。

典型流程：

1. 在搜索框输入关键词，例如 HashMap、volatile、索引失效。
2. 查看匹配到的题目和知识点。
3. 进入知识点详情。
4. 查看关联题目。
5. 开始专项练习。

## 5. 第一版范围

### 5.1 必做范围

第一版必须包含以下能力：

- Android 本地 App。
- 无需登录。
- Java 八股内置学习包。
- 内置题库。
- 题目分类。
- 知识点标签。

- 答案和解析。

## 6. 内容范围

### 6.1 初始学习包

第一版只内置一个学习包：

> Java 八股学习包

### 6.2 初始分类

建议第一版包含以下分类：

- JVM
- Java 基础
- 集合
- 并发
- Spring / Spring Boot
- MySQL
- Redis
- 计算机网络
- 操作系统
- 设计模式
- 项目场景题

### 6.3 初始题量

第一版正式完成时覆盖 50 道 Java 八股题。

这 50 道题需要覆盖主要分类，并且每道题都应包含分类、知识点、答案和解析，以支撑刷题、搜索、错题和知识点聚合能力。

### 6.4 题型范围

第一版支持：

- 单选题。
- 多选题。
- 判断题。
- 简答题。

简答题需要用户先输入自己的答案并提交；提交后系统展示正确答案和解析，用户再根据对照结果选择“通过”或“未通过”。简答题自评结果需要计入答题记录和正确率统计：通过视为答对，未通过视为答错。

## 7. 功能需求

### 7.1 首页

首页需要让用户快速进入核心学习动作。

需要展示：

- 今日学习入口。
- 继续刷题入口。
- 随机刷题入口。
- 分类刷题入口。
- 错题本入口。
- 搜索入口。
- 基础学习统计，例如已刷题数、正确率、薄弱知识点。

### 7.2 刷题

刷题页需要支持用户完成题目作答和即时反馈。

需要支持：

- 展示题干。
- 展示题型。
- 展示所属分类。
- 展示相关知识点。
- 单选题展示选项，并支持选择一个答案。
- 多选题展示选项，并支持选择多个答案。
- 判断题展示判断选项。
- 简答题允许用户输入自己的答案。
- 提交答案。
- 展示正确答案。
- 展示解析。
- 简答题提交后先展示正确答案和解析，再由用户选择通过或未通过。
- 标记收藏。
- 进入下一题。

刷题模式需要支持：

- 顺序刷题。
- 随机刷题。
- 分类刷题。
- 知识点刷题。
- 错题重刷。

### 7.3 错题本

错题本用于承接复盘闭环。

需要支持：

- 自动记录答错题。
- 展示错题列表。
- 展示错题所属分类和知识点。
- 查看题目详情、答案和解析。
- 重新练习错题。
- 标记已掌握。
- 按知识点查看错题数量。

错题移除规则：

- 用户标记“已掌握”后，该题不再出现在默认错题列表。
- 用户标记“已掌握”后，该题不需要定期再次出现。
- 已掌握错题仍应能在历史记录或筛选条件中被找到，避免用户误操作后完全丢失。

### 7.4 收藏题

收藏题用于保存用户主观认为重要或需要反复看的题。

需要支持：

- 在题目详情或刷题过程中收藏题目。
- 在收藏列表查看已收藏题目。
- 取消收藏。
- 从收藏列表进入题目详情或练习。

### 7.5 本地进度

第一版所有学习数据都保存在本地。

需要记录：

- 已做题目。
- 每次答题结果。
- 正确率。
- 简答题自评结果，其中通过计入正确，未通过计入错误。
- 已刷题数。
- 分类进度。
- 知识点掌握情况。
- 错题状态。
- 收藏状态。

### 7.6 搜索

第一版搜索为本地关键词搜索。

搜索范围：

- 题干。
- 选项。
- 答案。
- 解析。
- 分类名。
- 知识点名称。
- 知识点描述。

搜索结果需要展示：

- 匹配类型，例如题目或知识点。
- 标题或题干摘要。
- 所属分类。
- 难度。
- 是否做过。
- 是否答错过。
- 进入详情或开始练习的入口。

### 7.7 知识点学习地图

知识点学习地图是第一版主动学习能力的核心。

需要支持：

- 展示知识点列表。
- 按分类组织知识点。
- 展示每个知识点关联题目数量。
- 展示每个知识点的练习进度。
- 展示每个知识点的错题数量。
- 进入知识点详情。
- 从知识点详情进入专项练习。

知识点详情需要展示：

- 知识点名称。
- 所属分类。
- 简短说明。
- 关联题目。
- 用户在该知识点下的正确率。
- 用户在该知识点下的错题。

### 7.8 统计

第一版统计需要服务于“我最近哪里薄弱”。

需要展示：

- 总已刷题数。
- 总正确率。
- 分类正确率。
- 知识点正确率。
- 错题最多的知识点。
- 最近学习记录。

## 9. 关键产品规则

### 9.1 无需登录

用户打开 App 后应直接进入学习体验，不出现登录、注册或账号引导。

### 9.2 本地优先

第一版所有题库、记录、错题、收藏、统计均在本地完成。

### 9.3 内容先内置

第一版不支持用户导入题库，不支持从网络拉取题库。

### 9.4 学习包意识

虽然第一版只做 Java 八股，但产品概念上应保留“学习包”意识，避免把产品表达限制为单纯 Java 题库 App。

产品命名和文案应优先表达：

> 随心学是个人学习工具，Java 八股是第一批学习内容。

## 10. 第一版验收标准

第一版验收不按内部开发步骤拆分，只按最终可用体验验收。

### 10.1 基础体验

- 用户无需登录即可进入 App。
- 用户可以看到内置 Java 八股学习包。
- 用户可以在 10 秒内开始第一道题。
- 用户退出并重新打开 App 后，本地学习记录仍然保留。

### 10.2 刷题闭环

- 用户可以按顺序、随机、分类、知识点进入刷题。
- 用户可以完成单选题、多选题、判断题和简答题的学习流程。
- 简答题需要用户先输入答案并提交，再查看正确答案和解析进行比较，最后由用户选择通过或未通过。
- 用户提交或查看答案后，可以看到正确答案和解析。
- 用户答题记录会影响已刷数量、正确率和进度统计。
- 简答题自评结果会影响已刷数量、正确率、进度统计和错题本；选择未通过时进入错题本。
- 用户可以收藏和取消收藏题目。

### 10.3 复盘闭环

- 用户答错后，题目会进入错题本。
- 用户可以从错题本重新练习。
- 用户可以查看错题所属分类、知识点、答案和解析。
- 用户可以将错题标记为已掌握。
- 用户可以按知识点聚合查看错题和薄弱项。

### 10.4 主动学习

- 用户可以搜索题目和知识点。
- 用户可以查看知识点列表和知识点详情。
- 用户可以看到知识点关联题目。
- 用户可以从知识点详情进入专项练习。
- 用户可以看到分类和知识点维度的学习进度、正确率和错题数量。

## 11. 成功指标

第一版成功指标只使用客观、可验证的开发指标。

开发完成指标：

- 内置 Java 八股题库包含 50 道题。
- 50 道题均包含分类、知识点、答案和解析。
- 单选题、多选题、判断题、简答题四种题型均可完成答题流程。
- 简答题支持输入答案，并在提交后展示正确答案和解析。
- 简答题展示正确答案和解析后，支持用户选择通过或未通过；通过计入正确率分子，未通过计入错误并进入错题本。
- 顺序刷题、随机刷题、分类刷题、知识点刷题、错题重刷均可进入并完成至少一题。
- 答题记录、错题状态、收藏状态、学习进度均可本地持久化。
- 退出并重新打开 App 后，本地学习记录仍然保留。
- 搜索可以匹配题干、选项、答案、解析、分类名、知识点名称和知识点描述。
- 每个知识点详情页可以展示关联题目和该知识点下的学习统计。
- 错题本支持重新练习、标记已掌握，并按知识点聚合查看错题数量。

## 15. 第二版产品定位

第二版在第一版“本地刷题、复盘、搜索、知识点学习”闭环之上，引入 AI 辅助能力和知识库能力，让 SuiLearn 从固定题库工具升级为能够根据用户资料和学习表现生成内容、回答问题、辅助复习的个人学习工具。

第二版不追求一次性做成全能学习伙伴，而是聚焦两个核心变化：

- AI 辅助学习：围绕已有题库、错题和知识点，生成新题、相似题、简短解释和复习建议。
- 知识库学习：允许用户导入资料，把资料变成可搜索、可提问、可生成题目、可复习的学习内容。

第二版完成后的理想状态：

> 用户错了某类题之后，App 能帮用户生成针对性练习；用户导入一份学习资料后，App 能把它变成可搜索、可刷题、可复习的内容。

## 16. 第二版目标

第二版对应 `docs/chat.md` 中 V3 + V4 的合并范围。

第二版目标：

> 在第一版本地学习闭环基础上，接入 AI 和知识库能力，让用户可以围绕错题、知识点和自有资料获得个性化练习与问答支持。

第二版需要同时满足四类核心价值：

- 能生成：用户可以基于知识点、错题或资料生成可保存的新题。
- 能追练：用户可以针对错题和薄弱知识点生成相似题或专项练习。
- 能问答：用户可以围绕导入资料或知识库内容进行提问。
- 能沉淀：AI 输出内容需要经过保存、修正或删除后进入本地学习内容，不把一次性回答直接混入正式题库。

## 17. 第二版目标用户

第二版目标用户仍以第一版用户为基础，即正在复习 Java 面试知识的个人开发者，同时新增以下需求场景：

- 已经积累错题，希望获得更有针对性练习的人。
- 希望把自己的 Markdown、TXT、PDF 等资料转成学习内容的人。
- 希望围绕某份资料直接提问、搜索和生成题目的人。
- 希望探索 AI 学习工具能力，但仍希望保留本地优先和可控内容沉淀的人。

## 18. 第二版核心使用场景

### 18.1 错题后的针对性追练

用户完成刷题后，发现某个知识点反复出错，可以让 App 生成相似题进行追练。

典型流程：

1. 用户进入错题本或薄弱知识点页面。
2. 选择一个错题或知识点。
3. 请求生成相似题或专项练习。
4. 查看 AI 生成题目、答案和解析。
5. 用户选择保存、编辑后保存或丢弃。
6. 保存后的题目进入本地题库，并可参与刷题、错题和统计。

### 18.2 知识点解释和复习建议

用户对某个知识点理解不清，或最近某类题正确率较低，可以请求 AI 生成简短解释和复习建议。

典型流程：

1. 用户进入知识点详情或统计页面。
2. 查看相关题目、正确率和错题数量。
3. 请求生成知识点解释或复习建议。
4. 系统展示 AI 生成内容。
5. 用户可选择保存为学习笔记，或仅作为本次参考。

### 18.3 导入资料生成学习内容

用户有一份学习资料，希望转成可复习内容。

典型流程：

1. 用户进入知识库页面。
2. 创建或选择一个知识库。
3. 导入本地资料，例如 Markdown、TXT、PDF。
4. 系统从资料中提取知识点和摘要。
5. 用户基于资料生成题目。
6. 用户确认、编辑或删除生成内容。
7. 保存后的内容进入对应知识库和学习包。

### 18.4 基于资料提问和语义搜索

用户希望查找某个概念或直接提问。

典型流程：

1. 用户进入搜索或知识库页面。
2. 输入自然语言问题或关键词。
3. 系统从当前知识库中返回相关资料片段、题目、知识点或回答。
4. 用户进入资料片段、知识点详情、题目详情或继续追问。

## 19. 第二版范围

### 19.1 必做范围

第二版必须包含以下能力：

- AI 生成新题。
- 基于错题生成相似题。
- 基于知识点生成简短解释。
- 基于答题情况生成复习建议。
- AI 生成内容的保存、编辑、删除和丢弃。
- 导入本地资料，例如 Markdown、TXT、PDF。
- 从资料中提取知识点。
- 基于资料生成题目。
- 基于资料回答问题。
- 语义搜索。
- 知识库创建和管理。
- 不同知识库之间的内容隔离。
- AI 生成内容进入本地题库后的刷题、错题、收藏和统计支持。
- Web 前端界面，用于承载第二版的知识库管理、资料导入、AI 生成结果确认、语义搜索和资料问答等核心流程。

### 19.2 暂不包含

第二版明确不做：

- 面向多用户的账号体系。
- 云端同步。
- 社区、评论、排行榜。
- 付费、会员、商业化。
- 自动发布未经用户确认的 AI 生成题。
- 无限制自动爬取网络资料。
- 多端协同。
- 完整个人智能学习伙伴。
- 英语单词、古诗词等多学科正式内容包。

## 20. 第二版功能需求

### 20.1 AI 生成题

AI 生成题用于扩展练习内容，但必须保持用户可控。

需要支持：

- 从知识点详情发起生成题目。
- 从错题详情发起生成相似题。
- 从资料或知识库发起生成题目。
- 生成题目时明确题型、题干、选项、答案、解析、分类和知识点。
- 生成结果先进入待确认状态。
- 用户可以保存、编辑后保存、删除或丢弃生成结果。
- 保存后的题目成为本地题库的一部分。
- 保存后的题目可以参与刷题、错题本、收藏、搜索和统计。

### 20.2 相似题和专项练习

相似题用于解决“知道错了但缺少针对性练习”的问题。

需要支持：

- 从单道错题生成相似题。
- 从某个薄弱知识点生成一组专项题。
- 从最近错题较多的知识点生成小测。
- 展示生成依据，例如来源错题、来源知识点或来源资料。
- 用户确认保存后，才进入正式练习内容。

### 20.3 知识点解释和复习建议

AI 解释和复习建议用于辅助理解，不替代正式题库和解析。

需要支持：

- 在知识点详情页生成简短解释。
- 在统计页基于最近答题情况生成复习建议。
- 在错题本基于错题聚合生成复习建议。
- 复习建议需要指向可执行动作，例如重刷某类题、查看某个知识点、生成一组相似题。
- 用户可以保存有价值的解释或建议。

### 20.4 知识库管理

知识库用于组织用户导入资料和由资料生成的学习内容。

需要支持：

- 创建知识库。
- 查看知识库列表。
- 修改知识库名称。
- 删除知识库。
- 查看知识库中的资料、知识点、题目和学习记录。
- 在创建内容时选择所属知识库。
- 不同知识库的搜索、问答和生成结果需要有明确归属。

第二版可以先支持 Java 面试、Spring、MySQL 等知识库场景；英语单词、古诗词等多学科内容包仍留到后续版本正式展开。

### 20.5 资料导入

资料导入用于把用户已有学习材料转成可学习内容。

需要支持：

- 导入 Markdown。
- 导入 TXT。
- 导入 PDF。
- 展示资料导入状态。
- 展示资料标题、来源、导入时间和所属知识库。
- 支持删除已导入资料。
- 资料删除后，需要明确提示其关联的生成内容是否保留。

### 20.6 知识点提取

知识点提取用于让资料进入第一版已有的知识点学习地图。

需要支持：

- 从资料中提取知识点名称。
- 为知识点生成简短说明。
- 将知识点归属到对应知识库。
- 建立知识点与资料片段的关联。
- 建立知识点与生成题目的关联。
- 用户可以编辑或删除提取出的知识点。

### 20.7 基于资料问答

资料问答用于让用户围绕自己的资料快速获得解释和定位。

需要支持：

- 在知识库范围内提问。
- 在单份资料范围内提问。
- 回答需要尽量指向相关资料片段。
- 当资料中没有足够依据时，需要提示“不确定”或“资料中未找到明确依据”。
- 用户可以从回答进入相关资料片段、知识点或题目。

### 20.8 语义搜索

语义搜索用于补足第一版关键词搜索的局限。

需要支持：

- 搜索题目。
- 搜索知识点。
- 搜索资料片段。
- 搜索 AI 生成后保存的内容。
- 支持自然语言式搜索，例如“HashMap 为什么线程不安全”。
- 搜索结果展示匹配对象类型、标题或摘要、所属知识库、关联知识点和进入详情入口。

## 21. 第二版信息结构

第二版在第一版页面基础上新增或增强以下一级能力，并需要生成对应的 Web 前端界面，用于让用户在浏览器中完成第二版核心流程：

- AI 生成。
- 知识库。
- 资料。
- 语义搜索。
- AI 内容管理。

建议第二版包含以下新增页面或入口：

- 知识库列表。
- 知识库详情。
- 资料详情。
- AI 生成结果确认页。
- AI 内容管理页。
- 语义搜索结果页。
- 资料问答页。

第一版已有的首页、刷题、分类、错题本、收藏、搜索、知识点、统计和设置仍然保留，并需要能够识别第二版新增内容。

## 22. 第二版关键产品规则

### 22.1 本地优先，AI 可选

第二版引入 AI，但产品原则仍是本地优先。第一版已有题库、答题记录、错题、收藏和统计不应依赖 AI 才能使用。

### 22.2 AI 内容必须可控

AI 生成内容不能自动进入正式题库。用户必须能看到生成结果，并决定保存、编辑后保存、删除或丢弃。

### 22.3 生成内容需要可追溯

AI 生成题、解释和建议需要保留来源信息，例如来自哪个知识点、哪道错题、哪份资料或哪个知识库。

### 22.4 知识库边界清晰

用户选择某个知识库后，搜索、问答和生成内容应优先限定在该知识库范围内，避免不同知识库内容混杂。

### 22.5 不确定时要表达不确定

当资料不足、生成依据不足或回答无法确认时，系统需要明确表达不确定，而不是给出看似确定的学习结论。

## 23. 第二版验收标准

第二版验收建立在第一版能力可用的基础上。

### 23.1 AI 辅助学习

- 用户可以从知识点详情生成新题。
- 用户可以从错题详情生成相似题。
- 用户可以基于最近答题情况生成复习建议。
- 用户可以查看 AI 生成结果。
- 用户可以保存、编辑后保存、删除或丢弃 AI 生成结果。
- 保存后的 AI 题目可以进入刷题流程。
- 保存后的 AI 题目可以进入搜索、收藏、错题和统计。

### 23.2 知识库和资料导入

- 用户可以创建知识库。
- 用户可以导入 Markdown、TXT、PDF 资料。
- 用户可以查看已导入资料列表和资料详情。
- 系统可以从资料中提取知识点。
- 用户可以编辑或删除提取出的知识点。
- 用户可以基于资料生成题目。
- 用户可以删除资料，并看到关联内容处理提示。

### 23.3 RAG 问答和语义搜索

- 用户可以在知识库范围内提问。
- 用户可以在单份资料范围内提问。
- 问答结果可以关联到相关资料片段。
- 当资料不足以回答时，系统需要表达不确定。
- 用户可以使用自然语言搜索题目、知识点和资料片段。
- 搜索结果可以展示类型、摘要、所属知识库、关联知识点和详情入口。

### 23.4 第一版能力兼容

- 第一版内置 Java 八股学习包仍可离线刷题。
- 第一版错题本、收藏、统计和知识点页面仍可正常使用。
- 第二版保存后的 AI 题目可以复用第一版刷题、错题、收藏和统计闭环。
- 未配置或无法使用 AI 能力时，第一版核心学习能力不应被阻断。

## 24. 第二版成功指标

第二版成功指标只使用客观、可验证的开发指标。

- 至少可以从 1 个知识点生成 1 道题并保存到本地题库。
- 至少可以从 1 道错题生成 1 道相似题并保存到本地题库。
- 至少可以基于最近答题记录生成 1 条复习建议。
- 保存后的 AI 题目可以完成一次刷题流程。
- 保存后的 AI 题目答错后可以进入错题本。
- 至少可以创建 1 个知识库。
- 至少可以导入 Markdown、TXT、PDF 三类资料。
- 至少可以从 1 份资料中提取知识点。
- 至少可以基于 1 份资料生成题目。
- 至少可以在 1 个知识库范围内完成一次资料问答。
- 至少可以通过语义搜索找到题目、知识点或资料片段。
- 当资料不足以回答问题时，系统可以给出不确定提示。

## 25. 第二版角色影响

第二版需求会影响以下角色：

- 架构 Agent：需要确认 AI、知识库、资料导入、语义搜索和本地数据之间的边界，并判断是否需要服务端介入。
- 内容 Agent：需要定义 AI 生成题、知识点解释、复习建议的内容质量标准和人工修正规则。
- Android Agent：需要实现第二版新增页面、AI 生成结果确认、知识库管理、资料导入、语义搜索和第一版能力复用。
- Server Backend Agent：第二版开始可能介入 AI 调用、资料处理、RAG 和知识库能力；具体边界由架构 Agent 确认。
- Web Frontend Agent：第二版需要生成 Web 前端界面，覆盖知识库管理、资料导入、AI 生成结果确认、语义搜索和资料问答等核心流程；具体视觉和交互细节由 Web Frontend Agent 基于本 PRD 继续细化。
- 测试 Agent：需要围绕 AI 内容可控、知识库边界、资料问答不确定性表达、第一版能力兼容设计测试范围。
