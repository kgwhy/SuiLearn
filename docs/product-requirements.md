## 1. 产品定位

随心学 SuiLearn 是一款 Android 本地学习 App。第一版聚焦 Java 八股学习场景，目标是做出一个无需登录、开箱即用、能刷题、能复盘、能主动查知识点的个人学习工具。

第一版不追求复杂 AI 能力和多学科扩展，而是先证明一个最朴素但真实可用的闭环：

> 用户每天愿意打开 5 分钟，刷几道 Java 八股题，复盘错题，并能在想补某个知识点时快速找到相关内容。

## 2. 第一版目标

第一版直接按最终交付范围定义，对应 `docs/chat.md` 对话中 v0、v1、v2 的合并范围，不再拆成多个对外版本或阶段目标。开发过程中可以按任务拆分推进，但产品验收只看第一版整体是否形成完整可用的 Java 八股本地学习工具。

第一版目标：

> 让用户无需登录即可打开 App，围绕 Java 八股完成刷题、复盘、搜索和知识点专项学习。

第一版需要同时满足三类核心价值：

- 能刷题：用户可以通过顺序、随机、分类、知识点、错题等方式进入练习。
- 能复盘：用户答错后可以沉淀到错题本，结合收藏、解析、统计持续复习。
- 能主动学：用户可以搜索题目和知识点，围绕某个概念查看关联题目并专项练习。

第一版完成后的理想状态：

> 用户准备 Java 面试时，可以真实依赖 SuiLearn 完成日常刷题、错题复盘和知识点查漏补缺，而不是把它当作临时 demo。

## 3. 目标用户

第一版目标用户是正在复习 Java 面试知识的个人开发者，尤其是：

- 准备 Java 后端面试的人。
- 想利用碎片时间复习 Java 八股的人。
- 想把错题、知识点和复习进度沉淀在本地工具里的人。
- 当前阶段的核心用户也包括项目创建者本人。

## 4. 核心使用场景

### 4.1 碎片时间刷题

用户打开 App 后，可以快速进入刷题，无需登录、无需配置、无需选择复杂条件。

典型流程：

1. 打开 App。
2. 选择继续刷题、随机刷题或某个分类。
3. 回答题目。
4. 查看答案和解析。
5. 进入下一题。

### 4.2 面试前集中复习

用户在准备面试前，可以按 Java 八股分类集中复习。

典型流程：

1. 进入分类页。
2. 选择 JVM、集合、并发、Spring、MySQL 等分类。
3. 查看该分类进度和正确率。
4. 进入分类刷题。
5. 复盘分类下的错题。

### 4.3 错题复盘

用户刷题后可以回到错题本，集中处理薄弱题目。

典型流程：

1. 进入错题本。
2. 按全部错题或知识点筛选。
3. 查看题目、正确答案、解析。
4. 重新练习。
5. 对已经掌握的题目标记为已掌握。

### 4.4 主动搜索知识点

用户突然想复习某个概念时，可以直接搜索。

典型流程：

1. 在搜索框输入关键词，例如 HashMap、volatile、索引失效。
2. 查看匹配到的题目和知识点。
3. 进入知识点详情。
4. 查看关联题目。
5. 开始专项练习。

## 5. 第一版范围

### 5.1 必做范围

第一版必须包含以下能力：

- Android 本地 App。
- 无需登录。
- Java 八股内置学习包。
- 内置题库。
- 题目分类。
- 知识点标签。
- 刷题流程。
- 答案和解析。
- 错题本。
- 收藏题。
- 本地答题记录。
- 本地进度统计。
- 基础搜索。
- 知识点页面。
- 知识点关联题目。
- 错题按知识点聚合。

### 5.2 暂不包含

第一版明确不做：

- 登录 / 注册。
- 云同步。
- 服务端。
- AI 生成题。
- RAG 知识库。
- 文档导入。
- 多学习包切换。
- 英语单词包。
- 古诗词包。
- 社区、评论、排行榜。
- 复杂学习计划。
- 付费、会员、商业化。
- iOS 和 Web 版本。

## 6. 内容范围

### 6.1 初始学习包

第一版只内置一个学习包：

> Java 八股学习包

### 6.2 初始分类

建议第一版包含以下分类：

- JVM
- Java 基础
- 集合
- 并发
- Spring / Spring Boot
- MySQL
- Redis
- 计算机网络
- 操作系统
- 设计模式
- 项目场景题

### 6.3 初始题量

第一版正式完成时覆盖 50 道 Java 八股题。

这 50 道题需要覆盖主要分类，并且每道题都应包含分类、知识点、答案和解析，以支撑刷题、搜索、错题和知识点聚合能力。

### 6.4 题型范围

第一版支持：

- 单选题。
- 多选题。
- 判断题。
- 简答题。

简答题需要用户先输入自己的答案并提交；提交后系统展示正确答案和解析，用户再根据对照结果选择“通过”或“未通过”。简答题自评结果需要计入答题记录和正确率统计：通过视为答对，未通过视为答错。

## 7. 功能需求

### 7.1 首页

首页需要让用户快速进入核心学习动作。

需要展示：

- 今日学习入口。
- 继续刷题入口。
- 随机刷题入口。
- 分类刷题入口。
- 错题本入口。
- 搜索入口。
- 基础学习统计，例如已刷题数、正确率、薄弱知识点。

### 7.2 刷题

刷题页需要支持用户完成题目作答和即时反馈。

需要支持：

- 展示题干。
- 展示题型。
- 展示所属分类。
- 展示相关知识点。
- 单选题展示选项，并支持选择一个答案。
- 多选题展示选项，并支持选择多个答案。
- 判断题展示判断选项。
- 简答题允许用户输入自己的答案。
- 提交答案。
- 展示正确答案。
- 展示解析。
- 简答题提交后先展示正确答案和解析，再由用户选择通过或未通过。
- 标记收藏。
- 进入下一题。

刷题模式需要支持：

- 顺序刷题。
- 随机刷题。
- 分类刷题。
- 知识点刷题。
- 错题重刷。

### 7.3 错题本

错题本用于承接复盘闭环。

需要支持：

- 自动记录答错题。
- 展示错题列表。
- 展示错题所属分类和知识点。
- 查看题目详情、答案和解析。
- 重新练习错题。
- 标记已掌握。
- 按知识点查看错题数量。

错题移除规则：

- 用户标记“已掌握”后，该题不再出现在默认错题列表。
- 用户标记“已掌握”后，该题不需要定期再次出现。
- 已掌握错题仍应能在历史记录或筛选条件中被找到，避免用户误操作后完全丢失。

### 7.4 收藏题

收藏题用于保存用户主观认为重要或需要反复看的题。

需要支持：

- 在题目详情或刷题过程中收藏题目。
- 在收藏列表查看已收藏题目。
- 取消收藏。
- 从收藏列表进入题目详情或练习。

### 7.5 本地进度

第一版所有学习数据都保存在本地。

需要记录：

- 已做题目。
- 每次答题结果。
- 正确率。
- 简答题自评结果，其中通过计入正确，未通过计入错误。
- 已刷题数。
- 分类进度。
- 知识点掌握情况。
- 错题状态。
- 收藏状态。

### 7.6 搜索

第一版搜索为本地关键词搜索。

搜索范围：

- 题干。
- 选项。
- 答案。
- 解析。
- 分类名。
- 知识点名称。
- 知识点描述。

搜索结果需要展示：

- 匹配类型，例如题目或知识点。
- 标题或题干摘要。
- 所属分类。
- 难度。
- 是否做过。
- 是否答错过。
- 进入详情或开始练习的入口。

### 7.7 知识点学习地图

知识点学习地图是第一版主动学习能力的核心。

需要支持：

- 展示知识点列表。
- 按分类组织知识点。
- 展示每个知识点关联题目数量。
- 展示每个知识点的练习进度。
- 展示每个知识点的错题数量。
- 进入知识点详情。
- 从知识点详情进入专项练习。

知识点详情需要展示：

- 知识点名称。
- 所属分类。
- 简短说明。
- 关联题目。
- 用户在该知识点下的正确率。
- 用户在该知识点下的错题。

### 7.8 统计

第一版统计需要服务于“我最近哪里薄弱”。

需要展示：

- 总已刷题数。
- 总正确率。
- 分类正确率。
- 知识点正确率。
- 错题最多的知识点。
- 最近学习记录。

## 8. 信息结构

第一版建议包含以下一级页面：

- 首页。
- 刷题。
- 分类。
- 错题本。
- 收藏。
- 搜索。
- 知识点。
- 统计。

设置页第一版只需要承载必要能力：

- 查看当前学习包信息。

- 查看 App 版本。

## 9. 关键产品规则

### 9.1 无需登录

用户打开 App 后应直接进入学习体验，不出现登录、注册或账号引导。

### 9.2 本地优先

第一版所有题库、记录、错题、收藏、统计均在本地完成。

### 9.3 内容先内置

第一版不支持用户导入题库，不支持从网络拉取题库。

### 9.4 学习包意识

虽然第一版只做 Java 八股，但产品概念上应保留“学习包”意识，避免把产品表达限制为单纯 Java 题库 App。

产品命名和文案应优先表达：

> 随心学是个人学习工具，Java 八股是第一批学习内容。

## 10. 第一版验收标准

第一版验收不按内部开发步骤拆分，只按最终可用体验验收。

### 10.1 基础体验

- 用户无需登录即可进入 App。
- 用户可以看到内置 Java 八股学习包。
- 用户可以在 10 秒内开始第一道题。
- 用户退出并重新打开 App 后，本地学习记录仍然保留。

### 10.2 刷题闭环

- 用户可以按顺序、随机、分类、知识点进入刷题。
- 用户可以完成单选题、多选题、判断题和简答题的学习流程。
- 简答题需要用户先输入答案并提交，再查看正确答案和解析进行比较，最后由用户选择通过或未通过。
- 用户提交或查看答案后，可以看到正确答案和解析。
- 用户答题记录会影响已刷数量、正确率和进度统计。
- 简答题自评结果会影响已刷数量、正确率、进度统计和错题本；选择未通过时进入错题本。
- 用户可以收藏和取消收藏题目。

### 10.3 复盘闭环

- 用户答错后，题目会进入错题本。
- 用户可以从错题本重新练习。
- 用户可以查看错题所属分类、知识点、答案和解析。
- 用户可以将错题标记为已掌握。
- 用户可以按知识点聚合查看错题和薄弱项。

### 10.4 主动学习

- 用户可以搜索题目和知识点。
- 用户可以查看知识点列表和知识点详情。
- 用户可以看到知识点关联题目。
- 用户可以从知识点详情进入专项练习。
- 用户可以看到分类和知识点维度的学习进度、正确率和错题数量。

## 11. 成功指标

第一版成功指标只使用客观、可验证的开发指标。

开发完成指标：

- 内置 Java 八股题库包含 50 道题。
- 50 道题均包含分类、知识点、答案和解析。
- 单选题、多选题、判断题、简答题四种题型均可完成答题流程。
- 简答题支持输入答案，并在提交后展示正确答案和解析。
- 简答题展示正确答案和解析后，支持用户选择通过或未通过；通过计入正确率分子，未通过计入错误并进入错题本。
- 顺序刷题、随机刷题、分类刷题、知识点刷题、错题重刷均可进入并完成至少一题。
- 答题记录、错题状态、收藏状态、学习进度均可本地持久化。
- 退出并重新打开 App 后，本地学习记录仍然保留。
- 搜索可以匹配题干、选项、答案、解析、分类名、知识点名称和知识点描述。
- 每个知识点详情页可以展示关联题目和该知识点下的学习统计。
- 错题本支持重新练习、标记已掌握，并按知识点聚合查看错题数量。

## 12. 后续版本边界

由于本 PRD 第一版已经合并覆盖 `docs/chat.md` 对话中的 v0、v1、v2 范围，第一版之后再考虑：

- V3：AI 辅助生成题、相似题、复习建议。
- V4：资料导入、知识库、RAG、语义搜索。
- V5：多学习包，例如英语单词、古诗词。
- V6：个人智能学习伙伴。

这些能力不进入第一版，除非用户后续明确调整阶段目标。

## 13. 角色影响

本需求文档会影响以下角色：

- 架构 Agent：需要基于第一版范围确认 Android 本地架构和数据模型边界。
- 内容 Agent：需要准备 Java 八股初始题库、分类、知识点和解析。
- Android Agent：需要基于页面结构完成第一版 Android App，包括 UI、交互、本地域模型、本地数据和题库导入。
- Server Backend Agent：第一版暂无服务端职责，后续 V3/V4 再介入 Java Spring Boot 后端。
- Web Frontend Agent：第一版暂无 Web 职责，第三版再介入 React Web。
- 测试 Agent：需要围绕第一版最终验收标准设计测试范围。
