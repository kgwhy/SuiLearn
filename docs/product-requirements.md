## 背景与目标

### 背景

准备 Java 面试的个人学习者需要一个打开就能用的学习工具。现有学习方式往往分散在题库、笔记、搜索引擎和临时资料之间，用户很难在碎片时间里快速开始刷题，也很难把错题、知识点、搜索结果和复习进度沉淀到同一个可复盘的闭环里。

第一阶段要解决的是本地 Java 八股学习闭环：用户无需登录，打开 App 后就能围绕内置 Java 八股学习包完成刷题、复盘、搜索和知识点专项学习。第一阶段不追求复杂 AI、多学科、多端同步或社区能力，而是先证明一个朴素但真实可用的学习工具。

第二阶段要解决的是固定题库之外的个性化学习问题：用户做错题后希望获得相似题和针对性解释，用户有自己的资料后希望把资料变成可搜索、可提问、可生成题目、可复习的学习内容。AI 和知识库能力必须可控，不能让未经确认的生成内容直接污染正式题库。

当前首页还存在体验风险：启动时先出现 App / 首页占位信息，题包初始化后主标题很快变成“Java 八股学习包”，用户容易误以为 App 从“SuiLearn 随心学”自动跳转到了学习包详情页。产品需要稳定表达“随心学是学习工具，Java 八股是当前学习内容包”的层级。

### 目标

用户打开 SuiLearn 后，无需登录即可围绕 Java 八股完成刷题、复盘、搜索和知识点学习；即使后续引入 AI、知识库、资料导入、语义搜索和 RAG 问答，第一阶段本地学习闭环仍然稳定可用。

首页需要清晰表达产品身份和当前学习内容：主标题表达“SuiLearn 随心学”这一 App 身份，当前学习包作为副信息展示。AI 生成内容需要始终由用户确认后才能沉淀为正式学习内容，知识库和 RAG 能力需要边界清晰、来源可追溯。

### 非目标

本文不试图一次性解决社交学习、账号体系、云同步、多学科学习包、公开知识库市场、团队协作、完整长期计划系统或未经用户确认的 AI 自动发布能力。

本文不做技术架构、数据库 schema、API 契约或具体实现文件设计；这些内容需要由架构 Agent 在架构文档中确认。

## 功能需求

### 需求 1：首页与学习包信息层级

#### 用户故事

1. 作为初次打开 App 的用户，我希望看到稳定的“SuiLearn 随心学”首页身份，以便知道自己仍在 App 首页而不是被自动带到某个内容页。
2. 作为初次打开 App 的用户，我希望当前学习包以副信息展示，以便区分“App 名称”和“正在学习的内容包”。
3. 作为对页面变化敏感的用户，我希望首页加载完成后主标题不突变，以便不误判为发生了自动跳转。

#### 需求要点

- 首页主标题表达 App / 产品身份，优先展示“SuiLearn 随心学”或等价 App 名称。
- 当前学习包作为副信息展示，例如“当前学习包：Java 八股学习包”。
- 题包初始化、刷新或加载完成时，不应让学习包名称替代首页主标题。
- 学习包副信息可以显示加载态、占位态或明确的当前学习包状态。
- 本能力使用轻量 Spec Key：`SPEC-HOME-PACK-HEADER`。

#### 验收标准

- 用户打开 App 后停留在首页，首页主标题在加载前后保持稳定。
- 用户可以明确区分 App 名称和当前学习包名称。
- 录屏或手动验证中，不应出现类似“从 SuiLearn 自动跳转到 Java 八股学习包页面”的视觉误导。

### 需求 2：本地 Java 八股学习闭环

#### 用户故事

1. 作为准备 Java 面试的学习者，我希望打开 App 后无需登录即可进入首页，以便立刻开始学习而不被账号流程打断。
2. 作为碎片时间学习者，我希望在 10 秒内进入第一道题，以便利用通勤、排队或休息时间快速刷题。
3. 作为 Java 八股学习者，我希望看到内置 Java 八股学习包，以便知道当前 App 已经准备好可学习内容。
4. 作为按计划复习的用户，我希望按顺序刷题，以便完整覆盖题库。
5. 作为想快速自测的用户，我希望随机刷题，以便检查自己是否真正掌握知识点。
6. 作为面试前集中复习的用户，我希望按分类刷题，以便集中复习 JVM、Java 基础、集合、并发、Spring、MySQL、Redis、网络、操作系统、设计模式和项目场景等主题。
7. 作为发现薄弱点的用户，我希望按知识点专项练习，以便针对具体概念补强。
8. 作为不想依赖网络的用户，我希望题库、记录、错题、收藏和统计都保存在本地，以便没有网络时也能继续学习。

#### 需求要点

- 第一阶段以 Android 本地学习 App 为主，不引入登录、云同步、服务端依赖、社区能力或多端学习端。
- 第一阶段只内置一个学习包：Java 八股学习包。产品表达保留“学习包”意识，但不提供多学习包切换。
- 初始分类包括 JVM、Java 基础、集合、并发、Spring、MySQL、Redis、计算机网络、操作系统、设计模式和项目场景。
- 第一阶段正式完成时覆盖 50 道 Java 八股题，题目都需要包含分类、知识点、答案和解析。
- 首页需要提供今日学习、继续刷题、随机刷题、分类刷题、错题本、搜索和基础统计等入口。
- 本能力使用轻量 Spec Key：`SPEC-OFFLINE-CORE`。

#### 验收标准

- 用户无需登录即可进入 App。
- 用户可以在 10 秒内开始第一道题。
- 用户可以看到内置 Java 八股学习包。
- 顺序、随机、分类、知识点和错题练习入口均可进入并完成至少一道题。
- 未配置或无法使用 AI 能力时，第一阶段内置 Java 八股学习包仍可离线刷题。

### 需求 3：题型、答题反馈与复盘

#### 用户故事

1. 作为刷选择题的用户，我希望支持单选题、多选题和判断题，以便常见客观题都能完成作答和反馈。
2. 作为练习表达能力的用户，我希望支持简答题先输入自己的答案再查看标准答案，以便训练面试表达而不是只背选项。
3. 作为简答题用户，我希望查看标准答案后自行选择“通过”或“未通过”，以便系统可以把我的自评纳入正确率、进度和错题统计。
4. 作为学习者，我希望每道题展示题干、题型、分类、相关知识点、答案和解析，以便不仅知道对错，也知道为什么。
5. 作为犯错后的用户，我希望答错题目自动进入错题本，以便后续集中复盘。
6. 作为复盘错题的用户，我希望查看错题所属分类、知识点、答案和解析，以便定位错误来源。
7. 作为已掌握错题的用户，我希望把错题标记为已掌握，以便错题本可以反映当前仍需处理的问题。
8. 作为想保留重点题的用户，我希望收藏和取消收藏题目，以便建立个人重点题列表。
9. 作为正在刷题的用户，我希望可以返回上一题，以便回看题目、答案和解析，不必只能继续下一题或结束练习。

#### 需求要点

- 第一阶段题型包括单选题、多选题、判断题和简答题。
- 简答题采用用户输入答案、提交、查看标准答案和解析、再自评通过或未通过的流程。
- 用户答题后可以看到正确答案和解析。
- 简答题通过视为答对，未通过视为答错。
- 答错题目进入错题本，用户可以重新练习并标记已掌握。
- 用户可以收藏和取消收藏题目。
- 刷题过程中需要支持前后题导航：第一题不可返回上一题；非第一题可返回上一题；已到最后一题时，继续下一题会结束当前练习。
- 用户返回上一题时，应能在当前练习会话内回看该题已提交的答案、正确/错误结果、简答题自评状态、标准答案和解析；返回上一题不应删除或回滚已经产生的答题记录、错题记录、收藏状态或统计沉淀。

#### 验收标准

- 四种题型均可完成作答流程。
- 简答题可以输入答案，提交后展示标准答案和解析。
- 简答题自评结果会影响正确率、进度统计和错题本。
- 错题本支持查看错题详情、重新练习、标记已掌握。
- 收藏入口可以展示收藏题目，并支持取消收藏。
- 用户在第二题及之后可以返回上一题，第一题的“上一题”能力不可用或明确不可触发。
- 用户返回已提交过的上一题时，可以看到该题本次练习中的已选答案或简答答案、反馈结果、正确答案和解析。
- 用户返回上一题后，仍可以继续向后刷题或结束练习；已产生的答题记录、错题记录和统计不因返回上一题而丢失。

### 需求 4：搜索、知识点与统计

#### 用户故事

1. 作为主动查概念的用户，我希望搜索题干、选项、答案、解析、分类和知识点，以便快速找到相关内容。
2. 作为想系统理解知识结构的用户，我希望查看知识点列表和知识点详情，以便知道每个知识点关联哪些题目和进度。
3. 作为持续复习的用户，我希望查看已刷题数、正确率、薄弱知识点、学习天数和错题数量，以便判断复习是否有效。
4. 作为重新打开 App 的用户，我希望本地学习记录仍然保留，以便学习进度不会丢失。

#### 需求要点

- 搜索需要覆盖题干、选项、答案、解析、分类名称、知识点名称和知识点描述。
- 知识点详情需要展示关联题目和该知识点下的学习统计，并支持进入专项练习。
- 本地记录需要覆盖答题记录、错题状态、收藏状态、学习进度和统计数据。
- 基础统计包括已刷题数、正确率、薄弱知识点、学习天数和错题数量。

#### 验收标准

- 搜索可以匹配题干、选项、答案、解析、分类和知识点。
- 每个知识点详情页可以展示关联题目和学习统计。
- 用户退出并重新打开 App 后，本地学习记录仍然保留。
- 统计数据会随答题、错题和收藏行为变化。

### 需求 5：AI 辅助学习与内容确认

#### 用户故事

1. 作为做错题后的用户，我希望基于错题生成相似题，以便立即针对薄弱点追练。
2. 作为理解不清的用户，我希望基于知识点生成简短解释和复习建议，以便在刷题之外补理解。
3. 作为想扩展练习内容的用户，我希望基于题目、知识点、错题、资料或知识库生成新题，以便练习不局限于固定内置题库。
4. 作为谨慎使用 AI 的用户，我希望先查看 AI 生成题、答案和解析再决定是否保存，以便控制正式学习内容的质量。
5. 作为内容维护者，我希望编辑 AI 生成内容后再保存，以便生成内容可以被修正后沉淀。
6. 作为不满意生成结果的用户，我希望删除或丢弃 AI 生成内容，以便错误内容不会进入正式题库。
7. 作为长期学习者，我希望保存后的 AI 题目复用刷题、错题、收藏、搜索和统计闭环，以便新内容与原有学习流程保持一致。

#### 需求要点

- 第二阶段在第一阶段本地学习闭环之上引入 AI 辅助学习。
- AI 生成范围包括基于题目、错题、知识点、分类、资料或知识库生成新题、相似题、解释和复习建议。
- AI 生成内容不能自动进入正式题库。
- 用户必须能查看生成结果，并选择保存、编辑后保存、删除或丢弃。
- 保存后的 AI 题目进入正式学习内容后，需要复用刷题、错题、收藏、搜索和统计闭环。
- 本能力使用轻量 Spec Key：`SPEC-AI-CONTENT-GATE`。

#### 验收标准

- 用户可以从错题、题目、知识点、资料或知识库发起 AI 生成。
- 用户可以查看 AI 生成结果。
- 用户可以保存、编辑后保存、删除或丢弃 AI 生成结果。
- 未经用户确认的 AI 生成内容不会进入正式题库。
- 保存后的 AI 题目可以完成刷题流程，并进入搜索、收藏、错题和统计。

### 需求 6：知识库、资料导入、RAG 问答与语义搜索

#### 用户故事

1. 作为有自有资料的用户，我希望创建知识库并导入资料，以便学习材料可以被系统组织和利用。
2. 作为导入资料的用户，我希望看到资料标题、来源、导入时间、所属知识库和导入状态，以便知道资料是否可用。
3. 作为使用知识库的用户，我希望从资料中提取知识点，以便资料可以连接到题目、问答和复习路径。
4. 作为基于资料学习的用户，我希望在知识库范围内提问，以便回答优先来自我选择的资料集合。
5. 作为针对单份资料学习的用户，我希望在单份资料范围内提问，以便回答不混入其他资料内容。
6. 作为搜索资料的用户，我希望用自然语言语义搜索资料片段、题目、知识点和已保存 AI 内容，以便不必只依赖精确关键词。
7. 作为需要判断可信度的用户，我希望 AI 回答和生成内容标明来源，以便追溯来自哪个知识点、错题、资料或知识库。
8. 作为面对不确定问题的用户，我希望系统明确表达不确定，以便不会把不可靠回答当作确定知识。
9. 作为 Web 工作台用户，我希望在 Web 端管理知识库、导入资料、确认 AI 生成结果、搜索和问答，以便较重的资料处理流程可以在更适合的界面完成。

#### 需求要点

- 第二阶段引入知识库、资料导入、资料问答和语义搜索。
- 知识库用于组织用户导入资料和由资料生成的学习内容。
- 不同知识库之间的搜索、问答、生成和内容归属需要边界清晰。
- 资料导入需要展示导入状态，并保留资料标题、来源、导入时间和所属知识库等产品信息。
- 知识点提取结果需要支持用户确认、编辑、删除，并能归属到对应知识库。
- RAG 问答需要支持知识库范围和单份资料范围。
- 回答需要尽量展示来源，并在不确定时表达不确定。
- 语义搜索需要覆盖资料片段、题目、知识点和已保存 AI 内容。
- Web 工作台用于承载知识库管理、资料导入、AI 生成结果确认、语义搜索和资料问答等重流程。
- 本能力使用轻量 Spec Key：`SPEC-KB-BOUNDARY`、`SPEC-RAG-TRACEABILITY`。

#### 验收标准

- 用户可以创建、查看、修改和删除知识库。
- 用户可以导入资料，并看到导入状态、资料信息和归属知识库。
- 用户可以查看、确认、编辑和删除知识点提取结果。
- 用户可以在知识库范围和单份资料范围内提问。
- 回答可以展示来源；无法确定时明确表达不确定。
- 语义搜索结果可以展示类型、摘要、所属知识库、关联知识点和详情入口。

## 产品决策

- 当前文档是当前已确认产品规格，作为产品真相源。
- SuiLearn 采用 AI First 文档架构：当前规格 + Approved Proposal + Git 历史 + 轻量 Spec Key。
- 后续产品变更先写 Proposal；Proposal 进入 `Approved` 后可作为实现依据；实现完成后把稳定结论合并回当前规格。
- 不维护多份完整版本 PRD，不默认建立全量需求 ID；本文不承担历史需求库职责。
- 只有跨模块、高风险、测试或审查需要稳定引用的能力，才使用轻量 Spec Key。
- 当前保留的 Spec Key 包括：`SPEC-HOME-PACK-HEADER`、`SPEC-AI-CONTENT-GATE`、`SPEC-KB-BOUNDARY`、`SPEC-RAG-TRACEABILITY`、`SPEC-OFFLINE-CORE`。
- 产品核心表达是：随心学是个人学习工具，Java 八股是第一批学习内容。即使第一阶段只有一个 Java 八股学习包，也要避免把产品表达限制成单纯 Java 题库 App。
- 刷题流程支持在当前练习会话内回看上一题；该能力用于回看和继续学习，不承担撤销历史答题记录或重算统计的职责。
- 第二阶段可以先支持 Java 面试、Spring、MySQL 等知识库场景；英语单词、古诗词等多学科内容包留到后续版本。
- 架构边界、服务端介入程度、资料处理方式和 AI / RAG 技术细节由架构 Agent 在实现前进一步确认。

## 测试决策

- 测试应优先验证用户可观察行为，而不是内部实现细节。好的测试应该围绕“用户能否完成学习任务、页面是否表达正确状态、数据是否在用户视角下保留、AI 内容是否可控”来设计。
- 基础体验测试需要覆盖无需登录进入 App、首页可见、10 秒内进入第一道题、本地记录重启后保留。
- 首页启动体验测试需要覆盖加载前后主标题保持稳定、当前学习包作为副信息展示、用户不会看到学习包名称替代首页主标题。
- 刷题闭环测试需要覆盖顺序、随机、分类、知识点、错题重刷等入口，并至少完成一道题的作答、反馈和记录沉淀。
- 题型测试需要覆盖单选题、多选题、判断题和简答题。简答题重点验证“输入答案、提交、查看答案、选择通过或未通过、影响正确率和错题本”。
- 刷题导航测试需要覆盖第一题不可返回、第二题及之后可返回上一题、返回后展示本次练习内已提交答案和反馈、返回后仍可继续向后刷题，以及返回上一题不删除既有答题记录、错题记录和统计沉淀。
- 错题本测试需要覆盖答错进入错题本、查看错题详情、重新练习、标记已掌握和按知识点聚合。
- 收藏测试需要覆盖收藏、取消收藏、从收藏入口进入题目练习。
- 搜索测试需要覆盖题干、选项、答案、解析、分类、知识点名称和知识点描述的匹配。
- 知识点学习地图测试需要覆盖知识点列表、知识点详情、关联题目、知识点统计和专项练习入口。
- 统计测试需要覆盖已刷题数、正确率、薄弱知识点、学习天数和错题数量随答题记录变化。
- AI 辅助学习测试需要覆盖从错题、题目、知识点、资料和知识库发起生成，并验证生成结果可查看、可保存、可编辑后保存、可删除、可丢弃。
- AI 内容沉淀测试需要覆盖保存后的 AI 题目可以进入刷题流程，并进入搜索、收藏、错题和统计。
- 知识库测试需要覆盖创建、查看、修改、删除知识库，以及不同知识库之间内容不混杂。
- 资料导入测试需要覆盖导入状态、资料信息展示、导入失败反馈和资料归属。
- 知识点提取测试需要覆盖提取结果展示、确认、编辑、删除和归属知识库。
- RAG 问答测试需要覆盖知识库范围问答、单份资料范围问答、来源展示和不确定表达。
- 语义搜索测试需要覆盖资料片段、题目、知识点和已保存 AI 内容，并验证结果摘要、类型、归属和详情入口。
- 兼容测试需要覆盖未配置或无法使用 AI 能力时，第一阶段内置 Java 八股学习包仍可离线刷题。
- 现有测试类型可作为先例：Android 单元测试、导入器测试、本地仓储测试、运行时仓储切换测试、查询仓储测试和基础烟雾测试。后续新增测试应尽量复用这些测试层级，并在必要时补充面向完整用户流程的 UI 或端到端验证。

## 范围外

- 第一阶段不包含登录、注册、用户体系、云同步、排行榜、社区、打卡分享和复杂成就系统。
- 第一阶段不包含 AI 生成题、RAG 知识库、资料导入、自定义题库、多学习包切换、语音输入、视频课、iOS 版本和 Web 学习端。
- 第一阶段不支持用户从网络拉取题库，不支持用户导入题库。
- 第二阶段不包含社交学习、公开知识库市场、多人协作编辑、企业团队管理、自动制定长期学习计划、自动发布未经用户确认的 AI 生成题。
- 第二阶段不把 AI 回答直接等同于正式答案，不让 AI 内容绕过用户确认进入正式学习内容。
- 第二阶段不正式展开英语单词、古诗词等多学科内容包；这些属于后续多学习包版本。
- 首页启动体验修正不新增多学习包切换功能，只修正首页信息层级和启动体验表达。

## 补充说明

- 第一阶段成功指标只使用客观、可验证的开发指标：50 道内置题、四种题型可完成、刷题入口可达、记录可持久化、搜索和知识点详情可用、错题本可复盘。
- 第二阶段成功指标同样使用客观指标：用户可以生成并确认 AI 内容，保存后的 AI 题目可以完成刷题和错题流程，可以创建至少一个知识库，可以完成资料导入、语义搜索和资料问答。

- 第二阶段角色影响：架构 Agent 确认 AI、知识库、资料导入、语义搜索和本地数据之间的边界；内容 Agent 定义 AI 生成题、知识点解释、复习建议的内容质量标准和人工修正规则；Android Agent 复用第一阶段能力并实现新增学习流程；Server Backend Agent 可能介入 AI 调用、资料处理、RAG 和知识库能力；Web Frontend Agent 承载知识库工作台；测试 Agent 覆盖 AI 内容可控、知识库边界、资料问答不确定性表达和第一阶段兼容。
