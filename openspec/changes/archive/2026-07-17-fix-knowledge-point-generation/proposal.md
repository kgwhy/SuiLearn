## 背景与动机

当前知识点提取会把结构不完整的 AI 响应当作未处理异常。Web 工作台仍调用已弃用的同步接口，导致本可恢复的生成质量问题以 `Internal Server Error` 呈现，而不是可追踪的任务结果。

本变更在不伪造学习内容或引用的前提下提升结构化生成韧性：给已配置模型一次有限的修复机会，若仍失败则记录安全、可操作的任务失败结果。

## 变更内容

- 在结构化知识点校验前，对 OpenAI 兼容响应中无损的格式差异进行归一化，不补造学习内容或来源引用。
- 归一化后的首次响应未通过 schema 或引用校验时，仅携带校验失败信息发起一次修复请求，要求返回修正后的 JSON。
- 修复响应仍校验失败时，持久化知识点生成任务为 `FAILED`，使用稳定且面向用户的错误码与说明；不暴露原始模型输出。
- Web 资料提取操作从已弃用同步接口切换到现有异步任务提交接口，并在工作台展示任务状态和错误。
- 保持禁止关键词 fallback、占位知识点和自动确认的既有规则。

## 能力范围

### 新增能力

无。

### 修改能力

- `structured-knowledge-points`：定义无损响应归一化和一次有限的 schema 修复尝试，再将结构化知识点任务标记为失败。
- `durable-async-content-processing`：要求 Web 资料提取流程提交并展示持久化知识点生成任务，而非在 HTTP 请求中执行 AI 工作。

## 影响范围

- 后端：`KnowledgePointService`、OpenAI 兼容 AI 适配器、持久化任务错误分类，以及 `services/api/src/test/**` 下的聚焦 Java 测试。
- Web：`apps/web/src/**` 内的资料提取操作、工作台状态展示与回归测试。
- 契约：无需新增端点或持久化 schema；现有 `POST /materials/{materialId}/knowledge-point-generations` 成为 Web 客户端路径。
- 当前事实文档：`docs/product-requirements.md`、`docs/architecture.md` 与 `docs/tech-selection.md` 不修改，因为异步、基于证据的目标行为已在其中明确；本变更只记录实现修正。

## 范围与验收

- 仅有受支持字段别名或可移除 JSON fence 差异的响应，可在归一化后正常生成 DRAFT。
- 首次不完整或无效响应恰好触发一次语义修复请求，且不受传输层重试配置影响。
- 第二次无效响应产生持久化 `FAILED` 任务、安全说明且不新增知识点。
- 模型、网络或 Provider 故障不得被转换成生成内容，也不得泄露模型响应正文。
- Web 资料提取控件收到 HTTP 202、展示已提交任务，并显示最终成功或失败状态，而非 HTTP 500 提示。

## 非目标

- 不在本地补造缺失的定义、原理、场景、易错点或引用。
- 不为诊断持久化原始模型响应、资料正文、凭据、队列详情或对象存储键。
- 不增加第二个用户可见端点，也不修改数据库 schema。
